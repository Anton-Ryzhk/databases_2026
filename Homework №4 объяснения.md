*1)* ROLLUP создаёт иерархическую группировку: сначала по месяцам, затем добавляет итоговую строку со значением NULL в колонке month.

HAVING фильтрует группы после агрегации. Условие:
``` sql
having SUM(tf.amount) > 10000000000
or EXTRACT(month from f.scheduled_departure) is null
``` 

- Первая часть (SUM > 10 млрд) отсеивает месяцы с малой выручкой
- Вторая часть (month IS NULL) сохраняет итоговую строку, так как ROLLUP генерирует NULL для агрегированной строки

Без второго условия итоговая строка была бы отфильтрована, если общая выручка ≤ 10 млрд (маловероятно, но логически важно).

*2)* Почему нельзя COUNT(`*`): COUNT(`*`) считает все строки, включая NULL - строки от LEFT JOIN. Для аэропортов без прибывших рейсов это даст 1 вместо 0.  COUNT(f.flight_id) считает только непустые значения, возвращая 0 для "пустых" аэропортов.

Hash Right Join: PostgreSQL выбирает правое соединение, так как таблица airports меньше flights. Хеш-таблица строится по airports, затем сканируются flights с фильтром по статусу.

Разница между ON и WHERE:
- ON: фильтр применяется до соединения -> аэропорты без рейсов сохраняются с NULL
- WHERE: фильтр применяется после соединения -> NULL - строки отбрасываются, LEFT JOIN превращается в INNER JOIN

*3)* Неоптимизированный: функции EXTRACT(MONTH ...), EXTRACT(YEAR ...) применяются к каждой строке -> Seq Scan (полное сканирование таблицы), индекс не может использоваться.

Оптимизированный: диапазонный предикат >= '2017-08-01' AND < '2017-09-01' sargable -> используется Index Scan по индексу на scheduled_departure. 

*4)* NOT EXISTS эффективнее: PostgreSQL преобразует его в Hash Anti Join — строится хеш-таблица по ticket_flights (Business), затем сканируются flights с проверкой отсутствия в хеше.  NULL проблема: если подзапрос вернёт хотя бы один NULL, весь NOT IN вернёт UNKNOWN (не TRUE), и запрос вернёт 0 строк

*5)* Index Only Scan: индекс содержит все запрашиваемые поля (status для GROUP BY и COUNT). PostgreSQL читает только индекс, не обращаясь к таблице (heap).
Ускорение:
- Без индекса: Seq Scan читает всю таблицу
- С индексом: Index Only Scan читает только индекс
